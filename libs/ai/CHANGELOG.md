# Changelog

## [Unreleased]

### Added

- The `local` provider runs GGUF classifier models in process through `node-llama-cpp` (`node-llama-cpp-classify`), with Liquid D1 3B as `local/liquid-d1-3b`. A model is fetched on first use and shared by the whole process; until it is downloaded and loaded into memory, `classify` returns an error at once, and a failed fetch is retried on the next call. `ProviderClassifier.prepare` and `Provider.prepareClassifier` fetch and load a classifier model ahead of the first call and report whether it was downloaded. `download: false` in its config uses only model files already in `directory` and never downloads
- `AssistantMessage.errorStatus` holds the HTTP status of a failed request for the Anthropic, OpenAI Completions, OpenAI Responses, OpenAI Codex, and Google APIs. `isRetryableAssistantError`, the new `isProviderUnusableError`, and the new `providerUnusableReason` (`auth` or `quota`) judge a failure by this number: 429, 500, 502, 503, 504, 520, and 524 are retried, and 401, 402, and 403 mark the provider unusable and are not retried. For a message without it, they read the status from the error text only where it stands at the start or after `HTTP`, `status`, `error`, `error code`, `failed`, `returned`, `answered`, `(`, or a JSON `code`/`status` key, and only where the number is followed by the end of the text, `:`, `)`, `"`, `status code`, or an HTTP reason phrase, so a number such as `max_tokens: 402` or `error: 402 tokens requested` is not taken for a status. Without a status, a failure marks the provider unusable only when its text carries the provider's own error kind: a JSON `type`, `code`, or `status` of `authentication_error`, `permission_error`, `invalid_api_key`, `PERMISSION_DENIED`, or `UNAUTHENTICATED` for `auth`, or a quota code such as `insufficient_quota`, `billing_error`, or `payment_required` for `quota`, so `EACCES: permission denied` or `Disk quota exceeded` does not switch providers
- `AssistantMessage.errorResetsAt` holds the time, in epoch milliseconds, at which the provider said the limit behind a failed request resets. It does not change how the failure is judged; the status and the error kind still decide that
- `@msa/ai/utils/html-document` exports `htmlDocument({ title, style, body, head?, lang?, htmlAttributes?, imageSources? })`, which returns an `HtmlDocument` (a branded string) whose head declares the Content-Security-Policy `default-src 'none'; style-src 'unsafe-inline'; form-action 'none'`, with `img-src` only for the given `imageSources`, and in which every `<script` and `</script` of its parts is text. `escapeHtml` escapes text and attribute values for it
- `@msa/ai/utils/html-document` exports the two ways out for an `HtmlDocument`, and neither takes a plain string: `htmlReply(status, document)` builds a `text/html; charset=utf-8` response with `cache-control: no-store`, and `writeHtmlFile(write, path, document)` hands the document to the given file writer
- `@msa/ai/utils/script-output` exports the one way scripts touch files, child processes, and stdout: the `ScriptOutput` service (`scriptOutputLayer`) writes `.html` only from an `HtmlDocument` (`writeHtmlReport`), text only to `.txt`, `.md`, `.json`, `.jsonl`, `.js`, `.mjs`, `.cjs`, `.map`, `.ts`, `.rb`, or `SHA256SUMS` (`writeTextFile`), binary only to `.png` (`writeBinaryFile`), and copies, moves, or links a path only under its own extension (`copyFileTo`, `copyTreeTo`, `movePath`, `linkPath`); any other destination stops the script. It also carries `files` (read, list, stat, hash, make and remove directories, never write content), `path`, `processes`, and `interactive`. `processes.run` and `spawn` start only the commands in a closed list (`bun`, `msa`, `node`, `npm`, `pnpm`, `tar`, `vp`, `zip`, or a built binary named `msa`) without a shell; what a started program writes is up to that program. `files.makeTempDirectoryScoped` takes an optional parent directory. The module also exports `print` and `printError`, which write a line to stdout and stderr. `runMainWith(program, layer)` runs a script with `ScriptOutput` provided to the program and the layer

### Changed

- `@msa/ai/utils/oauth-page` exports `oauthSuccessReply(status, message)` and `oauthErrorReply(status, message, details?)`, which return the OAuth sign-in pages as `htmlReply` responses, in place of `oauthSuccessHtml` and `oauthErrorHtml`. The pages are built with `htmlDocument`, so they declare the Content-Security-Policy that runs no scripts, and the ChatGPT sign-in pages now also send `cache-control: no-store`
- The error classes `ModelsError`, `CodexStreamError` (`@msa/ai/api/codex-stream-error`), `RetryDelayExceededError` (`@msa/ai/api/retry-delay-exceeded-error`) are `Schema.TaggedError` classes. `new` takes one `{...}` object of their fields; the old positional arguments of `ModelsError` moved to the static `create(...)`, and `make({...})` builds one from the fields. `_tag`, `message` and the fields keep their names and values
- Constructing one of these errors checks its fields against the schema and throws when one does not match
- Encoding one of these errors to JSON lists its keys in the schema's order and drops keys the schema does not declare
- `stream()`, `complete()`, `streamSimple()`, and `completeSimple()` on `@msa/ai/compat` authenticate through `applyAuth`, the same path as `models.stream()`, instead of putting the provider's environment key into `apiKey`. `ANTHROPIC_AUTH_TOKEN` is sent as a bearer token, the model's `headers` and the resolved `baseUrl` are applied, and `options.signal` reaches the provider's auth resolver. When no auth resolves for a built-in provider, they no longer call the provider without a key: the request ends with `stopReason: "error"` and `Provider is not configured: <provider>`, as `models.stream()` does. The new `resolveAuth(providerOrModel, overrides)` returns the auth such a request would use

### Fixed

- OpenAI Completions requests to Ollama send `maxTokens` as `max_tokens`. Ollama ignores `max_completion_tokens`, so the limit had no effect and generation ran until the model stopped. The `ollama` provider and a `baseUrl` on port 11434 are taken as Ollama directly. For any other `baseUrl` outside OpenAI, OpenRouter, OpenCode, and Chutes, the first request with `maxTokens` reads the server root (the `baseUrl` without `/v1`) and treats a server that answers `Ollama is running` as Ollama; concurrent first requests share one check. Every chat response then corrects the answer: a stream whose first chunk carries `system_fingerprint: "fp_ollama"` marks the server as Ollama, any other first chunk marks it as not Ollama, so replacing the server behind the same URL takes effect from the next request without a restart. A root check that timed out, could not connect, was refused for credentials (401, 403, 407), was rate limited (408, 429), or failed with a 5xx decides nothing; the root is asked again at most once a minute until a check or a chat response settles it. `compat.maxTokensField` still overrides this and skips the check
